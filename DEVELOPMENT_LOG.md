# Shipment Tracker — журнал разработки

Этот файл — постоянная рабочая память проекта. Перед каждым следующим изменением сверяться с журналом, обновлять записи после проверки и не повторять исправленные ошибки.

## Текущая точка

- Репозиторий: https://github.com/wertretwetrertew-a11y/Shipment-Tracker
- Production URL: https://shipment-tracker-wertretwetrertew-4225.vercel.app
- Текущая версия интерфейса в исходнике: 0.2.4 (на 2026-10-13); production-публикация требует отдельной проверки.
- Стек: один статический `index.html`, HTML/CSS/JavaScript без сборщика.
- Хранение: localStorage на устройстве пользователя; экспорт/импорт JSON. Между устройствами синхронизации нет.
- Денежные правила: норма команды 75 т/месяц; фонд = max(0, тоннаж − 75) × 85 BYN; базовый оклад 1700 BYN, пропорционально часам до месячной нормы, без доплаты за сверхурочные.
- Источники отгрузок: Ozon, WB, Другое. Вес вводится в килограммах.

## План дальнейшей разработки

1. **Сразу после каждого изменения**
   - Обновить версию интерфейса и этот журнал.
   - Проверить HTML/JS на синтаксис и ссылки на существующие ID.
   - Опубликовать через Vercel, дождаться READY, проверить постоянный production URL.
   - Выполнить короткий browser smoke test; при тестовых записях удалить их и проверить возврат исходных значений.

2. **Ближайшие задачи**
   - Проверить экспорт и импорт JSON на тестовой резервной копии.
   - Добавить валидацию импортируемых данных (месяцы, массивы отгрузок, положительный вес, корректные даты), чтобы некорректный JSON не ломал приложение.
   - Добавить редактирование/удаление с более заметным подтверждением и доступными на телефоне кнопками.
   - Проверить мобильную ширину 320–430 px, верхнюю sticky-навигацию и safe-area на iPhone.
   - Исправить остаточные неточности UI-текста и доступности.

3. **Перед расширением**
   - Уточнить, как распределяется общий премиальный фонд между сотрудниками, прежде чем показывать личную премию.
   - Уточнить точную норму часов по каждому месяцу и правила праздничных/отпускных часов.
   - Обсудить облачную синхронизацию отдельно: она потребует backend, авторизации и правил доступа; сейчас данные не синхронизируются.

## Правила работы
- Не заявлять о выполненной публикации без подтверждения статуса и проверки публичной страницы.
- Не менять бизнес-формулы без согласования.
- Не использовать реальные пользовательские данные для тестов; тестовые записи всегда удалять.
- При неудачной публикации записывать ошибку и использовать подтверждённый безопасный путь восстановления.
